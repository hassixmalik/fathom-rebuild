# Plan: Fathom rebuild

## The hardest case in numbers
An 8-person, 1-hour call is roughly 9–10k words and about 1,200 transcript segments (5–10 s each), with frequent cross-talk and short interjections.
- **Size:** that's about 80 KB of JSON, around 20 KB gzipped. Send the whole transcript to the client in one go and **virtualize the list** rather than paginating it, so search and seeking work on the full meeting in the browser.
- **Speed and layout:** finding the active line from the playhead uses binary search on `start_ms`. Speaker lanes need 8 distinct, accessible colours. With 8 people, talk-time stats and topic chapters are what make an hour usable.
- **Cost:** pre-compute everything derived (talk time, chapters, summaries) in the seed, not at request time.

## Data model (Postgres on Neon via Vercel, Drizzle ORM)

```
users               id, name, email, avatar_url              -- single stub user, no auth
meetings            id, owner_id→users, title, platform(zoom|meet|teams),
                    started_at, duration_ms, status(scheduled|processing|ready),
                    media_url NULL, share_token NULL UNIQUE, calendar_event_id NULL
participants        id, meeting_id, display_name, email NULL, user_id NULL→users,
                    is_internal, color_index(0-7),
                    talk_time_ms, word_count, longest_monologue_ms   -- pre-computed at seed
transcript_segments id, meeting_id, participant_id, seq, start_ms, end_ms, text
                    INDEX (meeting_id, seq); GIN tsvector(text) for cross-meeting search
topics              id, meeting_id, start_ms, end_ms, title              -- chapters
summary_templates   id, key, name, sections JSONB [{key, title, kind: bullets|paragraph}]
summaries           id, meeting_id, template_id, status, generated_at, model,
                    content JSONB {sections:[{key, items:[{text, segment_ids:[]}]}]}
                    UNIQUE (meeting_id, template_id)
action_items        id, meeting_id, text, assignee_participant_id NULL, due_date NULL,
                    status(open|done), source_segment_id NULL, origin(ai|user), sort
highlights          id, meeting_id, created_by→users, start_ms, end_ms, title, note,
                    share_token NULL UNIQUE      -- a clip is a highlight that has a share_token
```

Design choices:
- **Every time value is a millisecond offset from the start of the meeting.** That one convention connects the transcript, highlights, topics and the player.
- **Summary items cite `segment_ids`.** Every bullet can then jump to the moment it came from, which is Fathom's most important interaction.
- **Assignees are participants, not users.** External attendees can own action items.
- **Highlights and clips share one table.** Sharing a highlight just sets a token.
- **Templates are data, not code.** The seed includes General, Sales (MEDDIC-style), Standup and 1:1, and switching templates only reads a different row.
- **No word-level timestamps.** Clips snap to segment boundaries, which is good enough for a one-day build.

## Screens, in priority order
1. **Meeting detail** `/meetings/[id]?t=` — the product itself:
   - Player across the top, with 8 speaker lanes and topic chapter markers.
   - Virtualized transcript that follows playback, with search and a speaker filter.
   - Right-hand tabs:
     - **Summary:** template switcher, and clicking a citation seeks the player.
     - **Action items:** toggle done, edit, reassign.
     - **Highlights.**
   - Selecting transcript text creates a highlight.
2. **Meetings list** `/meetings` — grouped by date, with search by title or participant, and a duration and attendees chip on each row.
3. **Clip share page** `/share/clip/[token]` — public and read-only. It plays only that time range and shows the transcript excerpt.
4. **My action items** `/action-items` — every meeting's items, grouped by meeting, filterable by status.
5. **Shared meeting** `/share/[token]` — a read-only version of screen 1.
6. **Templates** `/templates` — preview each template and pick the default.
7. **Upcoming / calendar stub, and settings** — static seeded data, built only if there's time.

## Stubs
- **Recording:** if `media_url` is null, a **virtual-clock player** drives play, pause, seek and speed, so transcript sync works without a video. If you add a sample MP4, it uses the same player interface.
- **Seed data:** one flagship 8-person, 1-hour meeting plus 6–8 smaller ones (2–4 people, 15–30 minutes), all as committed JSON loaded by a seed script. I'd generate the flagship transcript once with an LLM and commit it; the stats and chapters are then computed by the seed script.

## 6. Auto commit and push of the logs
At the end of every reply, the capture hook now commits only `.agent-logs/` and pushes the current branch. It leaves any other staged files alone. I tested this in a throwaway repo.

**Can it trigger itself or break capture? No:**
- Git doesn't fire Claude Code hooks, and the repo has no git hooks of its own.
- The capture hook always exits successfully, so it can never block the end of a turn or start a new one.
- The log entry is written before any git step, so a failed commit or push can't lose it. A failed push is retried with backoff, and anything still unpushed goes out at the end of the next turn.
